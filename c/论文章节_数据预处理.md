# 数据预处理与特征工程

## 2.1 原始数据概述

本研究使用的原始数据集 `2026_MCM_Problem_C_Data.csv` 包含了《Dancing with the Stars》（DWTS）节目第1至34季的完整比赛记录，共计 **421 条选手-赛季记录**，涵盖 51 个原始字段。数据集包含选手信息（姓名、职业、年龄、国籍）、舞伴信息、以及每周每位评委的详细评分。

### 2.1.1 数据质量挑战

原始数据存在以下关键问题，必须在建模前系统处理：

| 问题类型 | 具体表现 | 影响 |
|---------|---------|------|
| **结构性缺失** | 评委4列在大多数赛季为空（缺失率 >70%） | 直接求和会导致跨赛季不可比 |
| **语义性零值** | 被淘汰选手后续周次评分为 0.0 | 若不处理会错误拉低统计量 |
| **量纲不一致** | 部分赛季采用30分制、40分制或含加分项 | 跨赛季分析需归一化 |
| **非结构化目标** | `results` 列为文本（如 "Eliminated Week 4"） | 需解析为数值型生存周数 |

---

## 2.2 数据清洗流程

### 2.2.1 评分标准化

由于不同赛季评委人数不一致（3-4人），我们采用**单评委平均分**作为标准化指标：

$$\text{Score}_{\text{avg}}^{(w)} = \frac{\sum_{j=1}^{N_{\text{judges}}} \text{Score}_j^{(w)}}{N_{\text{judges}}}$$

其中 $N_{\text{judges}}$ 为第 $w$ 周实际参与打分的评委数量（忽略 NaN 值）。这确保了第4季（3位评委）与第8季（4位评委）的评分具有可比性。

### 2.2.2 缺失值与异常值处理

```
处理策略：
├── 零值处理：将代表"未参赛"的 0.0 替换为 NaN（防止拉低均值）
├── 评委缺失：按行计算有效评委数，动态调整分母
├── 地区缺失：celebrity_homestate 缺失填充为 "International"
└── 异常高分：保留奖励分（如 13.33），归一化至 [0, 10] 区间
```

### 2.2.3 目标变量解析

从 `results` 列提取关键信息：

| 原始文本 | 解析结果 |
|---------|---------|
| `"Eliminated Week 4"` | `weeks_survived = 4`, `placement = NULL` |
| `"1st Place"` | `weeks_survived = 最大周数`, `placement = 1` |
| `"Withdrew"` | `weeks_survived = 退赛周`, `final_result = "Withdrew"` |

## 2.3 特征工程

### 2.3.1 统计特征衍生

基于周度评分，我们为每位选手构建以下赛季级统计特征：

| 特征名称 | 计算方式 | 物理含义 |
|---------|---------|---------|
| `season_avg_score` | $\frac{1}{W}\sum_{w=1}^{W} \text{Score}_{\text{avg}}^{(w)}$ | 选手整体表现水平 |
| `season_score_std` | $\sqrt{\frac{1}{W}\sum_{w=1}^{W}(\text{Score}^{(w)} - \bar{\text{Score}})^2}$ | 表现稳定性 |
| `season_max_score` | $\max_w \text{Score}_{\text{avg}}^{(w)}$ | 峰值表现 |
| `season_min_score` | $\min_w \text{Score}_{\text{avg}}^{(w)}$ | 低谷表现 |
| `score_improvement` | $\text{Score}_{\text{last}} - \text{Score}_{\text{first}}$ | 进步幅度 |

### 2.3.2 类别变量编码

对职业类别（`celebrity_industry`）进行独热编码，保留高频类别：

```
is_Actor_Actress        # 演员
is_Athlete              # 运动员
is_TV_Personality       # 电视名人
is_Singer_Rapper        # 歌手/说唱
is_Model                # 模特
is_Comedian             # 喜剧演员
is_Social_Media_Personality  # 社交媒体网红
is_Radio_Personality    # 电台主持
```

此编码使得后续模型可以量化分析"运动员是否比演员更受粉丝欢迎"等关键问题。

## 2.4 淘汰数据与排名顺序重构

### 2.4.1 淘汰事件提取

原始数据仅记录每位选手的最终结果，缺乏逐周淘汰顺序。我们通过以下逻辑重构完整的**淘汰时序数据**：

```python
# 伪代码：淘汰事件提取
for season in 1..34:
    for week in 1..max_week:
        participants = 该周开始时的参赛者
        eliminated = 该周结束时被淘汰者
        survivor_scores = 幸存者的评委得分
        eliminated_score = 被淘汰者的评委得分
        
        记录: (season, week, participants, eliminated, scores)
```

**输出产物**：`问题1_批量结果_完整.csv`，包含 **435 条投票重构记录**：
- **324 条淘汰事件**（含 96 条双/多人淘汰）
- **111 条决赛选手记录**（冠军、亚军、季军）

### 2.4.2 排名顺序的重要性

淘汰数据隐含的排名约束是本研究的核心基础：

**淘汰约束**：被淘汰者的"评委分+粉丝票"总和必须是当周最低：

$$J_e + f_e \leq J_j + f_j, \quad \forall j \neq e$$

**决赛约束**：决赛名次反映最终投票高低：

$$f_{\text{冠军}} > f_{\text{亚军}} > f_{\text{季军}} > \cdots$$

这些约束为粉丝投票反演模型提供了**可行域边界**，使得原本不可观测的粉丝票可以被间接推断。

## 2.7 小结

本章完成了从原始数据到建模数据的全流程转换：

1. **数据清洗**：解决了评委数量不一致、零值语义、量纲差异等问题
2. **特征工程**：从 51 个原始字段扩展至 92 个可用特征
3. **淘汰重构**：从结果数据反向提取 435 条投票事件，建立排名约束
4. **选手汇总**：整合 408 位选手的完整画像，覆盖率达 96.8%

**关键洞见**：淘汰顺序和决赛名次蕴含了粉丝投票的隐式约束，这是后续反演模型的数学基础。通过预处理，我们将非结构化的比赛结果转化为了可用于凸优化采样的约束不等式系统。
